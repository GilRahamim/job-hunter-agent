The agents in Job Hunter

Two search agents share one SQLite database: the search pipeline (the default, a fixed LangGraph graph) and the opt-in agent loop, where the model picks its own tools. A third agent, CV tailoring, is designed but not built yet.

1 · Search pipeline jobhunter/agent.py

Deterministic batch run with one conditional edge. Only the top-N pre-scored jobs reach the LLM; with no key or provider: none it scores heuristically.

2 · Agent loop jobhunter/agent_loop/

Opt-in with run_agent.py --agent. The model chooses the next tool call until it saves goal_matches jobs or a budget runs out.

Guardrails stay in code, not in the model: dedupe and rule filters run inside search_jobs, a job must be read before it is saved, and max_steps / max_searches cap the loop.

3 · CV Tailoring agent planned

Specified in docs/ARCHITECTURE.md; jobhunter/tailor/ is still empty. Runs per job, on demand, and never adds facts that are not in the master CV.
